### 3. Who has not submitted the assignment due this week? (exact)

```sql
SELECT c.shortname, a.name AS assignment, a.due_at, p.user_ref
FROM activity AS a
JOIN course AS c ON c.course_id = a.course_id
JOIN participant AS p ON p.course_id = a.course_id AND p.role = 'student'
WHERE a.module = 'assign'
  AND a.due_at >= current_date AND a.due_at < current_date + INTERVAL 7 DAY
  AND NOT EXISTS (
      SELECT 1 FROM assignment_submission AS s
      WHERE s.cm_id = a.cm_id AND s.user_ref = p.user_ref AND s.status = 'submitted' AND s.latest
  )
ORDER BY c.shortname, a.name, p.user_ref
LIMIT 200
```

### 4. What is the average grade for each graded item in my course? (exact)

```sql
SELECT c.shortname, gi.item_name, count(g.final_grade) AS graded_students,
       round(avg(g.final_grade), 1) AS average_grade, gi.grade_max
FROM grade_item AS gi
JOIN course AS c ON c.course_id = gi.course_id
JOIN grade AS g ON g.grade_item_id = gi.grade_item_id
WHERE gi.item_type = 'mod'
GROUP BY c.shortname, gi.item_name, gi.grade_max
ORDER BY c.shortname, gi.item_name
```

### 5. Which activity has the highest drop-off? (exact)

```sql
WITH students AS (
    SELECT course_id, count(DISTINCT user_ref) AS n
    FROM participant WHERE role = 'student' GROUP BY course_id
), rates AS (
    SELECT a.course_id, a.section, a.cm_id, a.name,
           round(100.0 * count(DISTINCT cp.user_ref) FILTER (WHERE cp.completed) / s.n, 1) AS completion_pct
    FROM activity AS a
    JOIN students AS s ON s.course_id = a.course_id
    LEFT JOIN completion AS cp ON cp.cm_id = a.cm_id
    WHERE a.completion_tracked
    GROUP BY a.course_id, a.section, a.cm_id, a.name, s.n
), steps AS (
    SELECT *,
           lag(name) OVER (PARTITION BY course_id ORDER BY section, cm_id) AS previous_activity,
           lag(completion_pct) OVER (PARTITION BY course_id ORDER BY section, cm_id) AS previous_pct
    FROM rates
)
SELECT c.shortname, st.name AS activity, st.previous_activity,
       st.previous_pct, st.completion_pct, round(st.previous_pct - st.completion_pct, 1) AS drop_pct
FROM steps AS st
JOIN course AS c ON c.course_id = st.course_id
WHERE st.previous_pct IS NOT NULL
ORDER BY drop_pct DESC
LIMIT 10
```

### 6. Compare completion across my courses and explain the differences (exact)

```sql
WITH students AS (
    SELECT course_id, count(DISTINCT user_ref) AS students,
           count(DISTINCT user_ref) FILTER (WHERE days_since_last_login > 14 OR days_since_last_login IS NULL) AS inactive
    FROM participant WHERE role = 'student' GROUP BY course_id
), finished AS (
    SELECT course_id, count(*) FILTER (WHERE completed) AS completed
    FROM course_completion GROUP BY course_id
), rates AS (
    SELECT a.course_id, a.section, a.cm_id,
           100.0 * count(DISTINCT cp.user_ref) FILTER (WHERE cp.completed) / s.students AS pct
    FROM activity AS a
    JOIN students AS s ON s.course_id = a.course_id
    LEFT JOIN completion AS cp ON cp.cm_id = a.cm_id
    WHERE a.completion_tracked
    GROUP BY a.course_id, a.section, a.cm_id, s.students
), drops AS (
    SELECT course_id, max(prev - pct) AS biggest_drop_pct
    FROM (SELECT course_id, pct, lag(pct) OVER (PARTITION BY course_id ORDER BY section, cm_id) AS prev FROM rates)
    GROUP BY course_id
), grades AS (
    SELECT g.course_id, avg(100.0 * g.final_grade / gi.grade_max) AS avg_grade_pct
    FROM grade AS g JOIN grade_item AS gi ON gi.grade_item_id = g.grade_item_id
    WHERE gi.item_type = 'mod' AND gi.grade_max > 0
    GROUP BY g.course_id
)
SELECT c.shortname, s.students, coalesce(f.completed, 0) AS completed,
       round(100.0 * coalesce(f.completed, 0) / s.students, 1) AS completion_pct,
       round(100.0 * s.inactive / s.students, 1) AS inactive_14d_pct,
       round(d.biggest_drop_pct, 1) AS biggest_step_drop_pct,
       round(gr.avg_grade_pct, 1) AS avg_grade_pct
FROM course AS c
JOIN students AS s ON s.course_id = c.course_id
LEFT JOIN finished AS f ON f.course_id = c.course_id
LEFT JOIN drops AS d ON d.course_id = c.course_id
LEFT JOIN grades AS gr ON gr.course_id = c.course_id
ORDER BY completion_pct DESC
```

## Known limits

- `/ask` returns data, not prose. Question 6 asks to explain the differences; the API answers with the numbers that support an explanation (completion rate, inactive share, biggest drop), and the explanation sentence belongs to the Moodle plugin UI or a later step.
- Small models are not reliable SQL writers. The guard keeps wrong SQL from doing harm, but a query can be valid and still answer a different question; check the SQL shown with every answer.
- The paraphrase checks are lenient about shape. Question 9 asks "which students" and got per-course counts (28, 32, 41 not submitted), which matches the facts but is not a list. Question 12 asks "why" and got only the completion rate per course, without the inactive share or the drop-off size that example 6 returns.

## Notes from the 2026-10-04 run

These notes are written by hand; `make bench` overwrites this file.

- Model: `qwen2.5-coder:1.5b`, 986 MB on disk. `make init-model` pulled it in 95 s. The `ollama/ollama:0.35.1` image itself is 4.2 GB.
- Memory: with the model loaded the ollama container uses 1.5 GB (weights repacked for the CPU, 1.1 GB, plus the KV cache for `num_ctx` 8192 and compute buffers). On this machine the Docker VM had about 1 GB available with the whole stack up, and the first load was killed by the kernel (`llama-server process has terminated: signal: killed`, returned by `/ask` as 502 `model_unavailable`). The benchmark ran with this project's `db`, `moodle` and `cron` containers stopped to free 0.7 GB. `qwen2.5-coder:3b` needs about 2.3 GB and was not tried; 7b and 14b do not fit.
- Ollama underestimates the risk: it reports the VM's total memory as free (`free="7.6 GiB"`) and loads anyway, so an out-of-memory load shows up as a killed runner, not as a clear error.
- Prompt cache: the system prompt (rules plus schema, about 2100 tokens) is identical for every question and Ollama reuses it. With no examples, a second question costs about 100 ms of prompt evaluation instead of a few seconds. The six few-shot examples change with the question, add 800 to 1200 tokens, and are evaluated again every time at roughly 115 tokens/s, which is most of the 7 to 15 s of prompt time in the table. `EXAMPLES_TOP_K` trades accuracy for latency here.
- The paraphrased drop-off question failed after the retry: the final answer copied the last part of the drop-off example and left out the `rates` CTE it depends on, although the retry message named the missing table.
- GPU: there is no NVIDIA GPU on this machine. The `gpu` compose profile (`make up OLLAMA_PROFILE=gpu`) is written but has not been run.
